# Misdeal — Reward Cinematics 1.0 · Hero Development

Арт-пакет для `major_upgrade` («Развитие отряда») и `bonus_upgrade` («Ещё одна ставка»). Утверждённый концепт: `approved_reference.png`. Чистая художественная адаптация: `source/clean_master.png`. В игре использовать только `runtime/`. Preview — не игровой скриншот; изображения и надписи в нём демонстрационные, не импортировать как игровые данные.

## Внедрение
- `runtime/development_plate.webp`: чистая подложка 1280×720. Печатные рамки и кнопки уже на ней, не добавлять дополнительные панели. `layout_1280x720.json` задаёт абсолютные Rect2, координаты текста, палитру и локальные состояния.
- Три физические карточки. 1 вариант — центр, 2 — крайние, 3 — все. Незанятые ниши перекрыть соответствующим `slot_N_inactive.webp` (без кнопки, подписи, фокуса и ввода). Сохранять порядок настоящих offer ids, маппинг physical slot -> original offer index.
- Для каждой карточки использовать `CardArtCatalog.get_upgrade_texture(upgrade_id)`, существующий `ApprovedChoiceArt` и `ROLE_FALLBACK_ART` в той же очередности. Не использовать изображения из концепта/preview, не рисовать новых героев. Сохранить aspect ratio и nearest filtering.
- Название, роль, эффект и описание — только `HeroUpgradeData` и действующие методы reward.gd. Использовать имеющийся `UPGRADE_EFFECT_CARD_COPY` / `_get_upgrade_quick_effect()` для краткого текста, не скрывать отрицательные эффекты, не превращать сложный модификатор в выдуманную цифру. Полное описание доступно через существующий ПКМ. Если текст не помещается, переносить строки, не опускать размер ниже 15, дать прокрутку/детали. Цвет не единственный признак преимущества или недостатка: сохранить знаки и слова.
- Заголовок и реплика из `_setup_major_upgrade_reward` / `_setup_bonus_upgrade_reward`. Этап I–III вычислять из текущего active card tier только для major. Для bonus использовать короткое обозначение дополнительного развития и реальный прогресс, если доступен. Сохранить действующий hint, а также ПКМ. Не фиксировать stage или героя из концепта. Разместить длинные строки по доступной ширине.
- Состояния `slot_N_hover.png` / `slot_N_focus.png` — локальное мягкое выделение рамки, поверх фона, но под живым текстом/артом; не применять одновременно. `button_N_*.webp` — готовые состояния области кнопки. Все декоративные Control — MOUSE_FILTER_IGNORE. Единственная интерактивная цель для каждой карточки: её существующий Button, подпись «Выбрать» — CTA. Не вводить дополнительный клик подтверждения. Мышь, стрелки, Enter, ПКМ, штатная блокировка при commit.
- Не менять `_setup_initial_reward`, формирование офферов, `claim_major_upgrade`, `claim_bonus_upgrade`, `_finish_reward`, fallback +60 золота при пустом bonus, правила сохранений и переходов. В частности, major -> card reward (normal_loot, elite_artifact, death_wager) и death_wager -> bonus_upgrade. При смене режима полностью убрать presentation overlay и восстановить прежние ноды, сигналы и стили. Не изменять ранее утверждённые экраны добычи и реликвий.
- Сдержанные анимации, существующий звук; не добавлять вспышек, задержек или повторных начислений. Сохранить видимость живых данных, включая действующий run stats при необходимости через компактную свободную область, без перекрытия арта/рамок.
