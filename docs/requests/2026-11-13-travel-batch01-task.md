## 2. Цель: 3 сцены / 11 результатов / 1 общий релизный кандидат

Реализуй **все три сразу**:

| card_id | Исходы | Количество |
|---|---|---|
| `last_signal` | `truth`, `salvage`, `passed` | 3 |
| `gravedigger_shop` | покупка для `knight`, `ranger`, `mage`, `leave` | 4 |
| `lost_purse` | `safe`, `greedy`, `all_in`, `untouched` | 4 |

Всего **11 реально воспроизводимых визуальных вариантов**. В игре должны использоваться EXACT V3 изображения и подготовленные кадры/маски, а не старые V1/V2 варианты, браузерные GIF/APNG как замена Godot-анимации или заново сгенерированные персонажи.

Контракт логики:
- `last_signal:truth` существует только при активном Wizard Debt и наличии 20 золота; реальный resolver снимает долг и списывает 20. `salvage`: +22 золота. `passed`: без изменений.
- `gravedigger_shop`: покупка доступного развития выбранной роли за актуальную цену `RunState.get_gravedigger_shop_price()` с учётом состава отряда; одна успешная покупка сохраняется в игре как `event_outcome = "bought"` — этот существующий save-контракт **не менять**; `leave`: без покупки.
- `lost_purse:safe`: +15 золота; `greedy`: +35, -10 HP; `all_in`: +55, -25 HP; `untouched`: без изменений. Все значения применяются **единожды существующим `act_choice.gd`**, НЕ Travel-анимацией.

Все эти события **уже существуют**. Не создавай новые карточки событий, не включай дополнительную карту в Act1 и не меняй вероятности их появления.

## 3. Архитектура: расширять V2, а не строить V3-движок

Используй текущую архитектуру `TravelTransitionData`, `travel_catalog.gd`, `travel_transition.gd`, `SceneRouter` и существующую структуру panorama scripts. Создай три отдельных data resources (обычно `.tres`) и соответствующие локальные panorama scripts в согласованных с репозиторием каталогах. Сохрани длительность переходов **4 секунды**; вход и выход/skip — через действующий SceneTransition, без второго overlay router.

Обязательно:
1. Добавь `LOCATIONS` для всех 3 card_id в `scripts/travel/travel_catalog.gd`, **не удаляя прежние четыре**.
2. Добавь корректный `TEXT` для всех 11 визуальных вариантов, так как `context_for(...)` возвращает пустой словарь без текста. Для `last_signal` уже существующий TEXT сохранить по смыслу.
3. `act_choice.gd` сейчас формирует `travel_context` внутри `_finish()` из `RunState.get_event_outcome(...)`, который не содержит подробностей покупки и, возможно, не заполнен при `leave`. Добавь **только временную презентационную информацию** (например, `visual_action`/`choice_role`) после *успешного* разрешения выбора и до окончания перехода: для могильщика конкретную `knight/ranger/mage`, для `leave` явно `leave`; для кошеля используй зафиксированный choice; для сигнала существующий outcome. Не сохраняй эти поля в файле сохранения. Не угадывай купленное улучшение по составу отряда.
4. Логика выбора должна менять RunState ровно один раз, как до внедрения; **панорамы не имеют права** начислять золото, модифицировать HP/debt, выдавать апгрейд, писать save, вызывать `random`, вызывать resolver или менять отряд.
5. Игнорируй невозможные/неизвестные visual-action значения безопасно; при старом save или отсутствующем transient choice-role не показывай ложную покупку.
6. Пропуск, пауза, возврат к столу и защита от двойного запуска обязаны сохранять существующий контракт, включая сохранение после `_finish()`; обработчик завершения вызывается не более одного раза.

## 4. Арты и покадровая анимация

Мастер-изображения V3 — `source/original_master.png` (1672×941); финальные outcome PNG — 1280×720. Предусмотренные `layers/*`, `animation/*`, `layer_contract.json`, `animation_contract.json` — первичные материалы для реальной Godot-сборки. Перенеси в репозиторий **только необходимые runtime-ассеты**, плюс оригинальные мастера и provenance по действующему паттерну проекта; не коммить тяжёлые промежуточные MP4, контакт-листы, браузерные ревью и дубли существующих атласов героев, если это не требуется для runtime/rollback.

Координатные системы различаются: точные source_rect в master pixels переводить один раз по `x*1280/1672`, `y*720/941`; уже готовые 1280×720 исходы не масштабировать повторно. Использовать корректную alpha, вырезанные clean-underpaint и локальные object patches. Не рисовать полный финал поверх движущегося фона отдельным слоем с отличающимся сдвигом: появятся швы и двойники. Целевые плоскости и глубину согласовать с уже работающими Scene02–05.

Для `last_signal`:
- `salvage`: три реальные позы из `animation/salvage_action_0..2.png`, движущаяся чаша **не летит сама** и не дублируется; после действия остается пустой шест.
- `truth`: бумага падает/разрывается через `paper_pose_*`, конечная расписка сохраняется; чаша не исчезает.
- `passed`: башня и дежурство без изменения, только атмосфера.

Для `gravedigger_shop`:
- Четыре состояния: `knight`, `ranger`, `mage`, `leave`. Используй **исправленные V3** объекты и кадры, **не V2 с двумя головами** или огромными пергаментными плакатами. Во всех исходах **один живой пожилой могильщик**, без второй головы, дополнительного торса, лишних конечностей или появления другого NPC.
- Покупка видна у соответствующего подноса без изменений двух других; `leave` — все предметы и деньги остаются неизменными. Роль принимается только из разрешённых `knight/ranger/mage`.

Для `lost_purse`:
- `safe`: заметно взяты верхние монеты; `greedy`: нарушен кошель и усилилось напряжение руки; `all_in`: кошель полностью исчезает, не оставляя своего дубликата; `untouched`: всё исходное цело.
- В текущем тексте `all_in` упоминается кусок руки; арт V3 не показывает отрыв руки. **Не меняй игровой текст/механику по собственной инициативе**; отметь это как оставшееся художественное расхождение в итоговом QA, если визуально оно остаётся.

Не используй старые скриншоты V2 как финальные референсы вместо V3. Зафиксируй правильные источники через manifest SHA-256 и контрольные полноэкранные кадры.
