# V2 — обязательные указания для будущего Codex

Исторический художественный контракт V2. Пользователь отдельно разрешил полную интеграцию; кандидат реализован в текущем PR, без автоматического слияния. Пункты ниже сохраняют художественные ограничения исходного пакета.

1. Сохранить существующие механики и таблицу 31 исхода. Двадцать неизменённых действий не получают новых параметров V2.
2. Для 11 состояний с v2_fixed сначала копировать параметры сцены, затем накладывать **state.actor_stage**. Они продублированы в timeline.json. Маршрут, горизонт, высота, formation_lanes и progress_span образуют единый контракт; переносить только near_height недостаточно.
3. Никаких отдельных кистей, растянутых рукавов и горизонтальных рук. Монеты/чаша/корона/мешок меняются коротким локальным переходом состояния; сценическое сокращение получения предмета намеренное.
4. Кузница: с 0,44 с включить underpaint выбранного пустого крепления. Поверх — только соответствующий release_shield/quiver/focus.png, вырезанный из исходной базы, с переводом [5,-7] px и поворотом 1,6°, smoothstep 0,44–0,84 с. Альфа 1→0 между 0,70–1,06 с. Другие предметы не трогать. Это не пересылка предмета к случайной точке экрана и не новая выдача артефакта.
5. Масштаб — по max видимой высоте шести walk-кадров роли/ракурса, подошва — текущего кадра. Контактная тень получает те же foot и scale. Ближний масштаб не заменять миниатюрным ради глубины. Исходные атласы не редактировать.
6. Мост: в recruitment-ветках до найма Ranger не входит в проходящий отряд. При recruit с 0,90 с сидящий NPC исчезает и появляется ровно один Ranger actor. При loot_recruitment/abandon он остаётся отдельно, без Ranger actor. Обычные rush/scavenge не добавляют отдельного NPC. Реальная игра передаёт настоящий состав после выбора; не выдавать героя повторно.
7. Основа и связанные предметы остаются одной плоскостью с общим world transform; дымка отдельная. Никакой новой нарезки стен или объектов. Finals без проходящей партии — неизменённые эталоны, не runtime-видео.
8. MP4 служат ревью; не проигрывать их вместо динамического состава. Тестировать реальный Event → Travel → Table, solo/duo/trio, skip/pause, сохранение и существующий GUT/CI только при последующей разрешённой интеграции.
